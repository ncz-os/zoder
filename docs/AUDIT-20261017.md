repo, checked against the current source at base `fe0b8408` (master).

Method:

- Fresh `cargo build` on the Linux host; every `zoder <subcommand> --help`
  output compared against the docs (the committed `ZODER_CLI_SURFACE.txt`
  snapshot also matches the live CLI).

  provider.rs}` and `crates/zoder-cli/src/{review_diff.rs,eih_health.rs,
  provider_slots.rs}`.
- `corpus/model_corpus.json` and `pricing/catalog.json` checked for the
  model/provider route table.
- Internal link check (relative `.md` targets + anchors) scripted; result:
  all link targets exist.
- Current fleet rules applied: EIH carries only Nemotron/open-weight models;
  DeepSeek is direct-only (`api.deepseek.com`); TYDEUS :8010 nemotron35 is a
  valid backup under test; dead endpoints (TYDEUS :8002, the :4100 gateway,
  192.168.205.x, ollama :11434 on build hosts) and the old ngc-proxy must not
  appear as current facts. No dead endpoints were found in any `.md`.

## Fixes applied (with evidence)

**README.md**

- R1 — "OpenAI-compatible / LiteLLM endpoint" → "OpenAI-compatible endpoint".
  Evidence: `crates/zoder-core/src/pricing_sync.rs:10` — LiteLLM is a pricing
  data source, not a supported endpoint class.
- R2 — Pricing engine line: "optional live LiteLLM/OpenRouter cache" →
  "optional live price-list cache — the same LiteLLM + OpenRouter sources as
  the corpus". Evidence: `pricing_sync.rs:180` ("LiteLLM primary; OpenRouter
  fills …").
- R3 — Commands table missing 20+ subcommands (audit criterion 6). Added one
  row per missing subcommand with the live `--help` summary: `consult`,
  `finops`, `providers`, `pricing` (subcommands `refresh`/`show`), `reconcile`
  (openai|anthropic), `agents`, `tui`, `session`/`run`, `recipe`, `mcp`/
  `mcp-server`, `sop`, `configure`, `update`, `status`/`result`/`cancel`/
  `jobs`, `perf`, `eval`, `transfer`, `gate`, `mnemos`. Evidence: `zoder
  --help` (fresh build) + per-subcommand `--help`.
- R4 — "each tagged free or paid (from live pricing)" → "from the pricing
  catalog". Evidence: `corpus/model_corpus.json` is built by
  `scripts/build-public-corpus.py` from the static LiteLLM+OpenRouter price
  lists; the README's own "Corpus & pricing sync" section documents this.
- R5 — "The public zoder source refers only to a generic `enterprise`
  profile" → "carries commented-out templates only (config.enterprise.toml,
  config.ibm.toml, config.microsoft.toml, config.oracle.toml)". Evidence: the
  four committed template files all exist at repo root with the `[profile]`
  names `enterprise`/`ibm`/`microsoft`/`oracle`; every `[[providers]]` block
  is commented out.
- R6 — "the IBM/Microsoft templates" → "the committed vendor templates".
  Evidence: `config.oracle.toml` exists (same template shape).
- R7 — "data/pricing.json" → "pricing.json" (the `~/.zoder` file the
  installer seeds); "`zoder pricing sync`" → "`zoder pricing refresh`".
  Evidence: `install.sh:447-456` (seeds `$ZODER_HOME/pricing.json`);
  `zoder pricing --help` (subcommands are `refresh` and `show` — no `sync`).
